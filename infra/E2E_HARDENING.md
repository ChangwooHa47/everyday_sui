# 마무리 회귀 검증 — 2026-09-19

기준: 원격 main `24ada6e` (PR #17 포함). 조회한 모든 원격 브랜치의 커밋은 이 main의 이력에 포함돼 있다. 수정 작업은 `fix/e2e-hardening`에서 진행하며, 배포·provider 설정 변경·실제 거래는 수행하지 않았다.

## 수정과 회귀 범위

- 320px 화면의 커뮤니티 초상 너비와 검색 입력 최소 너비를 조정했다. 디자인 토큰과 기본 375px 구성은 유지한다.
- NFT 마켓·상세·컬렉션에서 이미지 404를 공통 `ResilientImage`로 처리한다. 배경 fallback을 표시하며, 없어진 Walrus 원본을 복구한 것은 아니다.
- NFT 마켓의 긴 u64 가격·재고가 그리드 너비를 밀어내지 않도록 줄바꿈과 최소 너비를 수정했다.
- 클라이언트 라우팅으로 상세 ID가 바뀌면 프로필/상품 상태를 새로 만든다. 이전 상품의 구매 버튼·후기·오류가 다음 상품에 남지 않는다.
- 수신 설정 확인 전 저장을 차단해 기존 차단 목록 덮어쓰기를 방지한다. 설정 조회/저장 실패와 보유 NFT 조회 실패를 분리한다.
- 빈 컬렉션의 선물 둘러보기 링크를 현재 상품 탭 `/market`으로 수정했다.
- 지갑 갱신 응답은 요청 당시 연결 세대가 유지될 때만 저장한다. 계정 전환 후 이전 응답은 새 세션을 저장하거나 지우지 못하며, 오래된 access token 폐기는 새 refresh cookie를 보내지 않는다.
- 기존 지갑 E2E의 로컬 DB를 `memory://`로 격리했다. 해당 지갑 UI 테스트 자체는 실행하지 않았다.

## 경계와 다음 검증

`npm run test:product`는 실제 Next 앱을 Chromium에서 실행하되 HTTP API를 fixture로 대체한다. 기존 legacy 세션 경로를 테스트 프로세스에서만 사용하며 로그인 UI는 열지 않는다. 허용한 로컬 앱/fixture 외 네트워크는 차단한다. 기존 `test:e2e`는 Spring baseline 검증용으로 그대로 유지했다.

따라서 이번 브라우저 통과는 실제 지갑 인증·Sui 구매·Walrus 보관·Seal 복호화·MemWal 장기기억 왕복·유료 이미지 생성 성공을 증명하지 않는다. API 테스트는 서명·세션 만료/회전/폐기, 구매자 격리, 기억 매핑/수신확정/교체, 중복 요청과 불확실한 거래 복구 등을 별도로 검사하지만 외부 공급자는 테스트 대역을 사용한다.

출시 전 남은 검증은 두 testnet 지갑으로 실제 구매→대화→NFT 수신→컬렉션 확인, 서비스 설정에 맞는 기억 저장/검색, 실제 공급자 장애 복구다. 해당 실행 환경과 거래/유료 호출 범위를 정한 뒤 진행해야 한다. 원격 push/merge 및 Railway/Cloudflare 변경은 이번 작업에 포함하지 않았다.

## 추가 요청: 425px와 첫 진입 라우팅

- `--app-max-width: 425px`를 앱 프레임·고정 내비게이션·채팅 목록 하단·홈/커뮤니티 캐러셀에 공유했다.
- 320/375/390/425/768px에서 프레임, 내비게이션, 스와이프 카드와 마켓 카드 경계를 검사했다. 확장된 브라우저 테스트 15개 통과.
- 공개 배포의 HTTP 응답은 200이며 서버 Location 리다이렉트는 없었다. 배포된 page JS에 `ensureAuth → listCharacters → 빈 목록이면 /create` 자동 이동이 실제 포함돼 있음을 확인했다. 사용자 브라우저의 지갑/쿠키 상태는 확인하지 않았다.
- 프로덕션 랜딩은 인증과 API 조회가 성공한 경우 `/home`으로만 이동한다. 인증/API 실패 시 랜딩에 남는다. legacy baseline의 탭→생성 경로는 테스트용 기존 동작을 유지한다.
- 로그인 UI는 열지 않았으며, 인증 실패/만료/목록 장애/빈 목록/기존 캐릭터 분기를 코드로 테스트했다. 웹 단위 테스트는 18개 통과.

## 추가 요청: 대화창 선물 검토 및 후속 수정

캐릭터→사용자: 일반 대화 후 이용권에 연결된 Listing과 giftPersona를 조회해 판단하고, 금고 거래 결과를 메시지에 연결한다. `confirmed` 카드만 도착 문구·컬렉션·거래 링크를 표시한다. 기능 활성화, 상품 allowlist, 한도, 금고 잔액, 외부 NFT 수신 동의 등이 필요하다. 이 검토는 운영 환경 활성화나 실제 수신을 증명하지 않는다.

사용자→캐릭터: 채팅에서 NFT를 보내거나 장착하는 UI/API 흐름은 확인되지 않았다. 마켓 직접 구매는 사용자 자신의 지갑으로 받는 기능이다.

발견했던 결함:

1. 외부 NFT 선물 확정 시 offer는 sold가 되지만, 채팅의 상품 상세 API는 active offer만 조회한다. 확정 카드에서 상품 이름/이미지를 로드할 수 없다 (`nft-market.ts` 상세 조회와 `chat/page.tsx` 상품 로딩).
2. 상품 메타데이터 요청 중 messages가 바뀌면 effect cleanup이 응답을 버리지만 requestedProducts에는 ID가 남는다. 다시 조회하지 않아 일반 상품도 카드 정보가 빠질 수 있다.
3. 거래 상태 폴링은 18회 후 멈추지만 준비 중 카드는 계속 남는다. 늦게 확정된 선물은 화면 재진입 없이 완료로 바뀌지 않을 수 있다.
4. 카드 문구는 확정 상태로 제한되지만 일반 AI 답변은 선물 판단/거래 전에 생성된다. 답변 본문의 '이미 보냈다' 같은 표현까지 거래 결과와 일치한다고 보장할 수는 없다.

후속 수정: sold 외부 NFT는 구매 불가능한 보관 메타데이터로 조회할 수 있게 했고, 구매 경로는 계속 실제 체인 검증을 거친다. 상품 로딩의 의존성을 메시지가 아닌 상품 ID 목록으로 분리했다. 상태 조회는 화면이 유지되는 동안 중복 없이 순차 반복하며, 언마운트 후 응답을 반영하지 않는다. 채팅 카드 이미지에도 실패 fallback을 적용했다. 일반 대화 프롬프트에는 거래 전 완료 표현을 금지하는 안내를 추가했다. 이는 모델 출력의 수학적 보장은 아니며, 실제 수신 증거는 confirmed 카드와 거래 영수증이다.

사용자→캐릭터 신규 전송/장착은 이번 오류 수정의 범위에 포함하지 않는다. 로그인 성공과 유효한 세션 복원은 캐릭터 보유 여부와 관계없이 홈으로 연결한다.

최종 로컬 회귀: 브라우저 16개(3분 이후 거래 확정 및 대화 중 메타데이터 보존 포함), 웹 단위 18개, API 74개, Move 26개. 검토에서는 sold 메타데이터가 구매 권한으로 사용되지 않는지, 지갑/상품 전환 시 이전 상태가 남지 않는지, 테스트가 실제 외부 결제나 사용자 DB를 건드리지 않는지를 확인했다. 사용자의 후속 승인에 따라 이 변경은 dev를 거쳐 main으로 전달한다. provider 직접 변경은 하지 않는다.
