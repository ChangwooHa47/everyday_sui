# 프로필 사진 생성 개선 리캡

> 캐릭터 생성 플로우의 초상(프로필 사진) 생성 품질·UX 개선 작업 기록
> 작성: 2026-07-08 · 관련 파일: `app/api/photo/route.ts`, `app/create/page.tsx`, `app/layout.tsx`

---

## 0. 배경 — 처음 두 가지 증상

1. **사진이 안 떴다** — 초상 고르기 화면에서 로딩 `✦`만 계속 뜨고 사진이 안 나옴
2. **하이드레이션 에러** — 콘솔에 `data-demoway-document-id` 관련 React 경고

---

## 1. 사진이 안 뜨던 진짜 원인 → 타임아웃

- 코드(`<img>`, `/api/photo`, Higgsfield 파이프라인)는 정상이었음
- 실제 원인: **Higgsfield 큐 지연**. 붐빌 땐 `queued`만 70초, 총 생성이 90~120초까지 감
- 서버 `generateSoul` 기본 타임아웃이 **120초**라 슬로우 큐에서 아슬아슬하게 잘림 → 빈 배열 반환 → "생성 실패" 또는 무한 로딩처럼 보임

**조치 (`app/api/photo/route.ts`)**
- `generateSoul` 타임아웃 `120s → 270s`, 폴링 `2.5s`
- `export const maxDuration = 300` — Vercel 배포 시 함수가 중간에 안 잘리게
- 로딩 화면에 "30초~2분 걸려요 ☕️" 안내 추가 (2분 무반응이 고장처럼 안 보이게)

## 1-b. 하이드레이션 에러 (별개, 무해)

- `data-demoway-document-id`는 브라우저 확장 **Demoway**가 `<body>`에 주입하는 속성 → 우리 코드 문제 아님
- `app/layout.tsx`의 `<body>`에 `suppressHydrationWarning` 추가로 경고 무시

---

## 2. "다 못생기게 나옴" → 스타일 미적용이 원인

- `style_id` 파라미터는 인터페이스에만 있고 **아무 데서도 안 넘기고 있었음** → raw base 모델로 뽑혀서 밋밋
- Higgsfield Soul엔 **106개 스타일 프리셋**이 있음
  - 목록 엔드포인트: `GET /v1/text2image/soul-styles`
  - 공식 SDK: `@higgsfield/client` 의 `getSoulStyles()`

**A/B 테스트 결론**
- 남/여 모두 **Realistic**(자연광 실물 셀카톤)이 미연시 몰입 최고
- **iPhone**도 강력 (진짜 셀카 느낌)
- Glazed Doll·Coquette 등은 인위적이거나 테마가 과함 → 기본값 부적합

**조치 (`app/api/photo/route.ts`)**
- `DEFAULT_STYLE_ID = Realistic` → `styleId` 안 넘기면 자동 적용, 넘기면 우선
- 텍스트 프롬프트 슬림화 (`studio lighting/professional` 제거 — 스타일과 충돌해 화보처럼 굳던 문제)
- **얼굴 가시성·복장 앵커(`PORTRAIT_FRAMING`) 추가** — Realistic이 캐주얼로 기울면 어깨 노출/과한 클로즈업이 나와서 "옷 입은 상반신·얼굴 프레임 노출" 강제 (이 API엔 네거티브 프롬프트가 없어 양성 앵커로 처리)

---

## 3. 스타일 번갈이 (natural ↔ iPhone)

- 요청: "첨에 natural로 뽑고, 다시 돌리면 iPhone, 또 돌리면 natural…"

**조치 (`app/create/page.tsx`)**
- `PHOTO_STYLES` 배열로 2종 순환: `natural`(Realistic) ↔ `iPhone`
- `genPortraits` 호출마다 `photoRound` 카운터로 다음 스타일 적용
- 로딩 화면: "**natural** 스타일로 4장 그리는 중…"
- 다시 만들기 버튼: "🔄 **iPhone** 스타일로 다시 만들기" (다음 스타일 미리보기)

---

## 4. 누적 갤러리 — 이전 사진도 같이 보고 고르기

- 요청: 다시 만들어도 앞 사진이 사라지지 말고 전부 놓고 고르게

**조치 (`app/create/page.tsx`)**
- `genPortraits`가 사진을 **덮어쓰지 않고 이어붙임** (`[...prev, ...new]`)
- 새 배치 뽑는 동안 기존 그리드 유지 + 뒤에 스켈레톤 4칸 표시
- 이미 고른 사진은 재생성해도 선택 유지
- 재생성 실패해도 기존 사진 보존
- 4장 넘으면 부제에 "· 총 N장 중 고르기"

---

## 5. 프로필 사진 브리프 — "어떤 사진일지" 물어보기

- 요청: 다들 웃는 사진이라 캐릭터성이 덜 보임 → 마지막에 원하는 사진을 묘사받아 반영. **단, 얼굴은 반드시 나오게**

**조치 (`app/create/page.tsx` — 브리프 화면 신설)**
- 컴파일(step 4) 후 바로 생성하지 않고 **브리프 화면(step 5-a)** 먼저 표시
- "○○의 프로필 사진, 어떤 느낌이면 좋겠어요?" + **"대신 얼굴이 나오는 사진이어야 해요!"**
- 자유 입력 + 탭하면 추가되는 예시 칩 (무표정 정면 / 나른한 옆얼굴 / 턱 괸 새침 / 도도한 눈빛 / 무심한 표정…)
- "그냥 알아서 뽑아줘" 옵션

**조치 (`app/api/photo/route.ts` — 브리프 처리)**
- `portraitBrief` 파라미터 추가
- 한국어면 `PROMPT_MODEL`(gpt-4o-mini)로 짧은 영어 이미지 프롬프트로 **자동 번역** (영어면 통과)
- 프롬프트 조립: `외모 + 유저브리프 + 얼굴가시성앵커(face clearly visible) + 스타일`
- 앵커를 `facing camera → face clearly visible in frame`으로 완화 → 표정·포즈는 자유롭게, 얼굴은 항상 프레임에

**검증:** "무표정으로 창밖 보는 시크한 분위기" → 창가에서 밖 보는 안 웃는 시크한 얼굴, 얼굴 정상 노출·건전 복장 확인 ✅

## 6. 인터뷰 페이즈 어긋남 + 모델 격상

- 증상: 외모 페이즈인데 분위기/성격을 묻는 등 질문이 페이즈와 안 맞음. 서버는 `phase` 라벨만 강제하고 질문 내용은 안 막아서 모델(gpt-4.1-mini)이 페이즈 밖으로 셌음

**조치 (`app/api/interview/route.ts`)**
- 모델 격상: 인터뷰 전용으로 분리 → `INTERVIEW_MODEL ?? PROMPT_MODEL ?? "gpt-4.1"` (채팅용 mini와 분리, 더 올리려면 `.env.local`에 `INTERVIEW_MODEL` 지정)
- **페이즈별 포함/제외 범위(`PHASE_SCOPE`) 못박기** — "외모=겉모습만, 성격·분위기·패션 금지" 식으로 각 페이즈에 ✅허용/🚫금지를 시스템 프롬프트 최상단에 주입
- 검증: 외모→얼굴상 / 스타일→패션 / 성격→관계역학, 세 페이즈 모두 범위 내 질문 확인 ✅

> 참고 모델 현황: 채팅 `CHAT_MODEL=gpt-4.1-mini` · 인터뷰/컴파일 `gpt-4.1` · 요약 `gpt-4o-mini` · 브리프 번역 `PROMPT_MODEL`

## 8. Soul 2.0 신규 엔드포인트 전면 이전 (웹과 결과가 달랐던 이유 해결)

- 웹(higgsfield.ai)과 결과가 다르던 원인:
  1. **`style_strength` 미전송** — 웹은 스타일 강도를 걸지만 우린 서버 기본값(약하게)으로 발림
  2. **구 엔드포인트 사용** — `/higgsfield-ai/soul/*`(구) vs `/v1/text2image/soul`(신규 Soul 2.0)
  3. **프롬프트 과다** — 스타일 고유 결을 품질·구도 단어가 희석

**조치 (`lib/higgsfield.ts` 전면 재작성)**
- 신규 엔드포인트로 이전: 제출 `POST /v1/text2image/soul { params }` → 폴링 `GET /v1/job-sets/{id}`
- 응답: `jobs[].results.raw.url` (batch 4 = job 4개). 파라미터: `width_and_height`, `quality`, `style_id`, **`style_strength`**, `custom_reference_id`, `custom_reference_strength`, `image_reference`
- 구버전(`aspect_ratio`/`resolution`/`status_url`/`soul/standard`) 완전 폐기
- `generateSoul(params, opts)` — `mode` 인자 제거 (참조 유무로 자동)

**조치 (`app/api/photo/route.ts`)**
- 신규 시그니처로 호출, `width_and_height:"1536x2048"` + `quality:"1080p"`
- `DEFAULT_STYLE_STRENGTH = 0.9` 추가, `styleStrength` 파라미터로 캐릭터/장면별 조절 가능
- Soul ID 있을 때 `custom_reference_strength: 1`
- 검증: 앱 route로 초상 생성 → 웹 감성의 자연광 캔디드 셀카 확인 ✅

> 남은 미세조정: `style_strength` 최적값(0.7/0.9/1.0) 눈으로 확정, 프롬프트 추가 다이어트
