# 마켓 캐릭터 상세 콘텐츠 기획

작성일: 2026-09-12. 대상 화면: `apps/web/app/community/detail/page.tsx`.

## 목표

마켓 목록에서 캐릭터를 고른 사용자가 상세 화면에서 **어떤 사람인지, 나와 어떤 관계가 될지, 실제 대화가 어떤 느낌인지** 빠르게 판단하게 한다. Tinder에서 참고할 점은 스와이프나 장식이 아니라 사진 뒤에 이어지는 자기소개·관심사·관계 목적·생활 정보의 순서다. 현재 카드, 섹션, 칩, CTA를 재사용하며 새로운 UI 기능을 늘리지 않는다.

유사 서비스에서 확인한 공통점은 다음과 같다.

- [Tinder 프로필](https://www.help.tinder.com/hc/en-us/articles/115003339043-Editing-your-profile)은 사진 다음에 소개, 관심사, 라이프스타일, 관계 목표, 언어·직업·학교·도시처럼 상대를 판단할 정보를 둔다.
- [Replika](https://help.replika.com/hc/en-us/articles/115001070951-What-is-Replika)는 관계 설정, 성격, 기억과 함께 시간이 지나며 관계가 달라지는 경험을 강조한다.
- [Nomi 시작 가이드](https://nomi.ai/nomi-knowledge/nomi-101-a-beginners-guide-to-getting-started-with-your-ai-companion/)는 성격과 관계 맥락, Shared Notes의 배경 설정을 결합한다.
- [Kindroid 성격 설정 문서](https://kindroid.ai/v2/docs/customizing-personality/)는 배경, 핵심 기억, 응답 지침, 예시 메시지를 캐릭터 일관성의 주요 입력으로 사용한다.

## 상세 페이지에 표시할 내용

| 순서 | 표시 내용 | 사용자가 판단하는 것 | 현재 데이터 |
| --- | --- | --- | --- |
| 1 | 이름, 관계 유형, 성별 | 기본 정체성과 원하는 관계 | 기존 공개 필드 재사용 |
| 2 | 한 문장 소개 | 이 캐릭터의 가장 강한 매력 | `summary` 재사용 |
| 3 | 평소에는 | 기존 배경 설정의 짧은 요약 | `background` 재사용 |
| 4 | 대화할 때 나는 | 말투, 답장 길이, 표현 방식 | `speechStyles` 재사용 |
| 5 | 우리 관계 | 생성할 때 선택한 관계 | `relationshipType` 재사용 |

`appearance` 장문은 사진으로 이미 전달되는 정보가 많으므로 우선순위를 낮춘다. 외모·성격·배경은 기존 생성 결과를 2문장·약 180자 이내로 줄인다. 정확한 위치, 학교·회사 실명, 내부 시스템 프롬프트, 구매자의 기억은 공개하지 않는다.

## 콘텐츠 작성 규칙

- 새 소개를 만들지 않고 생성된 `summary`를 사용한다.
- 외모·성격·배경은 의미를 추가하지 않고 앞의 두 문장만 표시한다.
- 캐릭터가 선물할 수 있다고 표시하려면 해당 Listing의 NFT allowlist와 예산이 실제로 활성화돼 있어야 한다.

## 예시

현재 `서준` 설정을 상세 콘텐츠로 풀면 다음 정도다.

- **한 문장 소개:** “건축 모형 붙이다가도 네 연락은 바로 보는 편이야. 밤에는 별 얘기보다 오늘 있었던 일이 더 궁금하고.”
- **평소의 나:** 건축 대학원에서 작업한다. 마감 전에는 밤을 자주 새우고, 새벽에 작업실 근처를 걸으며 사진을 찍는다.
- **우리 관계:** 연인

## 구현 순서

1. 기존 `summary`, `relationshipType`, `personality`, `appearance`, `background`, `speechStyles`만 사용한다.
2. 상세 응답에서 장문을 요약하고 전체 시스템 프롬프트·기억과 분리한다.
3. 기존 상품은 필드가 없어도 현재 상세 화면으로 정상 표시하는 하위 호환을 유지한다.
4. 상세 화면의 기존 섹션과 칩에 위 내용을 순서대로 연결한다.
5. 긴 한국어, 필드 일부 없음, 작은 화면, 미리보기 소진 상태를 검사한다.

## 테스트넷 기억 기준

장기기억의 이번 완료 기준은 **testnet에서 설정된 보관기간 동안** 승인 기억을 저장하고 다시 회상하는 것이다. 현재 구현은 지갑 소유자·delegate·활성 상태를 확인하고 package+Listing namespace로 캐릭터별 검색 범위를 나눈다. 실제 testnet에서 저장, 새 SDK 인스턴스 회상, 다른 소유자 거절, 다른 캐릭터 검색 결과 없음까지 확인했다.

영구보관과 자동 갱신은 testnet 완료 조건이 아니다. 현재 기본 보관 요청은 7 epochs다. 화면과 문서에서 무기한 기억으로 표현하지 않고, 보관기간이 지난 데이터의 지속성을 보장하지 않는다.
